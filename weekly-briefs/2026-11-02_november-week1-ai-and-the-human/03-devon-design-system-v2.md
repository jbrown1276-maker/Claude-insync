## 3. The seam — one change

**The terminating tick is now adaptive in length.** v1 fixed it at 96 px. Sarah's v2 AI items are longer, and a fixed 96 px tick left only 224 px of the 332 px AI column for text, which forced nearly every item to wrap two or three lines. That inflated AI's column height and made AI's half *more present* — exactly what Elena's row E-21 warns against.

**The tick always ends at x 424, four pixels short of the seam axis, with the closed 2 × 10 px cap.** That is where the meaning lives and it is unchanged. What varies is the start: the tick runs from the end of the item's longest line plus 16 px, clamped to **[40, 110] px**. 110 px is §4.2's third-of-column ceiling. AI text wraps against a 300 px measure, which puts most items on one line.

The effect is that the tick *is* the gap between the text and the boundary. Nothing crosses the seam, and the arrow test is verified mechanically on every export: **0 AI-gray pixels right of the axis on all five columned assets.**

## 9. Production Handoff Notes — changed sections only

### 9.2 Export settings, and two rasterizer traps

Unchanged: SVG source plus PNG @1x and @2x for every asset, sRGB, PNG mandatory before any social, email or CMS use (**L-2**). Email assets carry **no alpha channel**.

The pipeline rasterizes with **`qlmanage` (WebKit) + Pillow**, and two of its behaviours will silently corrupt output if unhandled:

1. **A non-square SVG is scaled to fit the square thumbnail's height, not its width.** A 1200 × 600 header rendered at `-s 1200` comes back as a 2× render clipped to the left half. Both headers were wrong in the first v1 export because of it. **Fix: pad the SVG to a square viewBox in the same user units before rendering, then crop the content box.** Deterministic, and it is in the pipeline.
2. **RGBA output must be flattened onto `#F3F4F6` explicitly**, and for email assets the alpha channel must be dropped, because a transparent PNG inverts unpredictably in dark mode.

### 9.3 Generated-layer correction — one refinement

Steps unchanged: regrade cool/high-key/flat, correct the layer's own background to `#F3F4F6` exactly, feather internal edges, pinstripe off.

**The ground correction uses a piecewise-linear curve, not an additive offset.** An offset that lands the background median on `#F3F4F6` pushes highlights past 255: measured, it clipped **8.31% of G2 and 3.06% of G3 to pure white**, and the palette forbids pure `#FFFFFF` as a ground. The curve maps 0→0, the sampled median→ground, and 255→255. Result: all four layers land their background median exactly on (243, 244, 246) with **0.00% pure-white clipping**.

### 9.4 Logo handling — standing rule (row D-14)

**A third-party SVG whose fills live in a `<style>` block loses them on inline embedding, and every element that is not a `<path>` is the one that vanishes silently.**

All four InSync logo files define fills through CSS classes, and each hides exactly one class-styled `<rect>` — the wordmark's "i" stem. A path-only extractor shipped the company name as "nsynctraining" across 14 SVGs and every PNG derived from them. The two BUG files also use a **different class prefix** (`st0`) and a **different attribute order**, so a regex tuned to the horizontal file would have failed on the mark in a second, non-obvious way.

**The rule, not the patch:**

1. Parse with an XML parser, never a regex. Attribute order varies between files from the same set.
2. Resolve the class→fill map from the `<style>` block; honour any pre-existing inline `fill` or `style` fill first.
3. Emit **every** drawable element type — `path, rect, circle, ellipse, polygon, polyline, line` — each with an explicit fill, in document order so paint order is preserved.
4. **Assert emitted drawable count == source drawable count before the markup enters any asset.** Horizontal lockup = **21** (20 path + 1 rect). Bug mark = **11** (10 path + 1 rect). White variants: assert every fill is `#fff`.
5. Verify structurally **and** with a pixel scan of the stem box. Never with a file count.
